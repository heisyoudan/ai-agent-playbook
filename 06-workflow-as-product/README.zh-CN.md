# 06 — 把工作流当作产品来设计

[日本語](README.ja.md) · [English](README.md) · **简体中文**

## 为什么需要工作流

任务设计、上下文隔离和角色定义可以改善单次会话。但如果人每次都必须记住并重新构建这些做法，质量仍然依赖个人纪律。

工作流把方法变成可执行系统。它决定任务如何进入、哪个角色行动、需要什么证据、何时可以改变状态，以及失败后怎样回到安全位置。

## 我为什么构建 Maestro

我希望本 Playbook 中的原则不只存在于一次成功会话里。Maestro 最初就是为了把任务契约、角色边界、结构化交接、质量门和可恢复状态转换写入系统。

两者的关系很简单：

```text
Playbook = 方法论和运行原则
Maestro  = 可执行的工作流框架
```

框架不是方法论的来源，而是方法论得以实践、验证和持续改进的环境。

## 模板驱动执行

### 自由理解与模板驱动

| 模式 | 行为 | 风险 |
|---|---|---|
| **自由理解** | Agent 根据一般指令临时创造流程。 | 判断漂移，输出不稳定。 |
| **模板驱动** | Agent 遵循规定的正常路径，异常时切换到规定的例外路径。 | 行为受约束并且可检查。 |

```text
正常模板
  ↓ 发现异常
案例模板
  ↓ 案例完成
明确交接到下一阶段
```

### 主模板

每个角色和状态需要：

- **目标**——本阶段要达成什么；
- **步骤**——具体执行什么；
- **完成条件**——离开阶段前必须具备什么证据；
- **允许案例**——哪些例外可以中断正常路径。

### 案例模板

每类异常需要：

- **触发条件**——什么情况进入案例；
- **适用范围**——适用于哪些角色和状态；
- **步骤**——怎样处理异常；
- **完成条件**——何时认为案例解决；
- **交接**——接下来谁根据什么状态行动。

## 压缩正常路径，详细说明异常

工作流越成熟，正常路径应该越短。只有当规则能够实际降低歧义、错误或沟通成本时，才增加它。

- 用新规则替换过期规则，而不是无限叠加。
- 删除重复模板和已经失效的运行知识。
- 对少见但危险的路径保持明确，因为在那里即兴处理的代价最高。

**规则不是需要不断扩张的收藏，而是需要持续打磨的产品。**

## 质量门

质量门决定阶段是否可以转换。

```text
Dev
  ↓ Gate：日志存在；构建和规定检查通过
QA
  ↓ Gate：测试结果和证据已经记录
Sage / 收口
```

条件不满足时，下一阶段不能开始。质量门把质量从愿望变成结构要求。

## 原子回滚

工作被驳回或退回时，三件事必须同时发生：

```text
1. 记录原因和证据。
2. 修改状态。
3. 生成下一步交接。
```

如果先改变状态、之后才记录原因，下一个角色看到的就是无法解释的转换。把三步视为一次操作，可以避免这个空档。

## 单一事实来源

聊天记录不是可靠的任务数据库。它不完整、难查询，而且经常包含相互竞争的解释。

把权威状态保存在一个结构化系统中：

```text
当前任务状态   → tasks
执行历史       → journal entries
质量门证据     → gate runs
状态转换历史   → transition requests
补充上下文     → task notes
```

Agent 应直接读取权威数据，而不是依赖某个人重新讲述会话。

## 工作流是一种可复用产品

工作流被固化后，可以在不同项目、Agent 和平台之间复用。

```text
平台无关的核心模板
        ↓ 派生
Codex / Copilot / 其他平台指令
```

平台文件只是交付格式，不是事实来源。应维护核心方法，再从中派生适配层。

## 指令驱动工作的实际形态

### 没有工作流系统时

人需要反复重建背景、收集文件、列出约束、解释完成条件、总结结果并准备交接。每个循环都在增加说明和传递成本。

### 有工作流系统时

```text
Sage 发布任务
  ↓ 自动生成结构化任务和 Dev 指令
Dev 执行并记录证据
  ↓ 生成 QA 指令
QA 独立验证
  ↓ 记录例外或关闭任务
```

人仍然负责决策和高风险批准，但不必在每次转换时手工重建普通上下文。

### 这个差异意味着什么

价值不在自动化本身，而在于：**把方法论固定为可执行结构，并减少人和 Agent 之间的摩擦。**

任务契约、职责隔离、明确约束、模板、质量门和结构化交接，使指令驱动的工作流成为可能。缺少这些基础时，新工具只是把同样的说明成本搬到另一个位置。
