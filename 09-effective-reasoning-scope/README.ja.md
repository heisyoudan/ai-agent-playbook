# 09 — 有効な推論範囲

**日本語** · [English](README.md) · [简体中文](README.zh-CN.md)

**状態：ドラフト（章の骨格）。** 成熟度：**Observed Pattern（観察されたパターン）** — 長期の実践で繰り返し現れているが、安定した方法論としてはまだ整理されていない。継続的な証拠は[リサーチ・インキュベーター](../research/README.ja.md)で追跡する。

## この章が扱う問い

Agent は、どれだけの材料を同時に推論させると信頼性が落ち始めるのか。

第02章はタスクの大きさを扱い、第04章はコンテキストの分離を扱う。推論範囲は第三の変数である。ある判断に対して、Agent が同時に保持すべき事実はどれか。逆に、信号を薄めるだけの事実はどれか。

## なぜこの章が必要か

「もっとコンテキストを与える」はよくある助言であり、しばしば誤りである。ある地点を超えると、追加の材料は理解を増やさない。重要な2行を200行の中に埋もれさせ、矛盾を見落としやすくし、判断を改善しないまま費用だけを増やす。

したがって推論範囲は、便利さの問題ではなく設計の決定である。Agent が何に気づけると期待するか、そして何を静かに無視するかを決める。

## この章に属すると想定される概念

- 利用可能なコンテキストと、関連するコンテキストの区別
- セッション単位ではなく、判断単位の範囲
- 範囲過多の症状：無視される矛盾、自信のある無関係、改善なき費用増
- 実行前に範囲を絞る技法
- 推論範囲と、タスク粒度・コンテキスト分離の関係
- 品質要因だけでなく、費用と遅延の要因としての範囲

## 現在の成熟度

実ワークフローで観察されているが、境界は定性的にしか説明できていない。有効な範囲を測る実用的な方法はまだない。
