# 09 — 有效推理范围

[日本語](README.ja.md) · [English](README.md) · **简体中文**

**状态：草稿（章节框架）。** 成熟度：**Observed Pattern（已观察到的模式）** —— 在长期实践中反复出现，但尚未稳定为方法论。持续积累的证据记录在[研究孵化器](../research/README.zh-CN.md)中。

## 本章要回答的问题

Agent 同时推理多少材料之后，可靠性开始下降？

第 02 章控制任务大小，第 04 章隔离上下文。推理范围是第三个变量：对某个判断而言，Agent 必须同时掌握哪些事实？而哪些事实只会稀释信号、反而有害？

## 为什么需要这一章

“给更多上下文”是一条常见建议，也常常是错的。超过某个点之后，追加材料并不会增加理解：它把关键的两行埋进两百行里，让矛盾更容易被忽略，并在不改善判断的前提下推高成本。

因此，推理范围是设计决策，而不是便利性问题。它决定了 Agent 能被期望注意到什么，以及它会静默忽略什么。

## 预计纳入的概念

- 可用上下文与相关上下文的区别
- 范围以判断为单位，而不是以会话为单位
- 范围过载的症状：被忽略的矛盾、自信的无关内容、成本上升但没有改善
- 执行前收窄范围的技术
- 推理范围与任务粒度、上下文隔离的关系
- 范围作为成本与延迟的驱动因素，而不只是质量因素

## 当前成熟度

在真实工作流中已被观察到，但边界目前只能定性描述；还缺少可用的“有效范围”度量方式。
