# 16 — スケールするガバナンスと意思決定圧縮

**日本語** · [English](README.md) · [简体中文](README.zh-CN.md)

**状態：ドラフト（章の骨格）。** 成熟度：**Working Hypothesis（作業仮説）** — スケールの問題は観察されているが、提案する仕組みはまだ検証されていない。追跡は[リサーチ・インキュベーター](../research/README.ja.md)で行う。

## この章が扱う問い

ガバナンスは、ボトルネックにならずにプロジェクトとともに拡大できるのか。

## なぜこの章が必要か

すべての意思決定を人間がレビューする前提のガバナンスはスケールしない。しかも静かに劣化する。レビュー担当者はパターンで承認するようになり、レビューは実質的な統制ではなくなる。

**意思決定の圧縮（Decision Compression）** とは、繰り返される判断を、規則・既定値・テンプレート・チェックリストとして一度だけ符号化し、毎回議論し直さずに適用できるようにすることを指す。その際、判断の根拠は取り出せる形で残す。エンジニアリングチームが標準や規約を使うのと似ているが、これを Agent の成果物に対して意図的に適用する。

リスクは明白で、それも仮説の一部である。見直されない圧縮された決定は、レビューされていない規則になる。理由を誰も覚えていない規則は、正しく修正することが難しい。

## この章に属すると想定される概念

- 圧縮候補としての、繰り返される意思決定
- 圧縮された意思決定としての規則・既定値・テンプレート・チェックリスト
- 明示的な適用範囲を伴う、先例の委譲
- 圧縮を改訂可能に保つための根拠の記録
- 圧縮された決定を再び開く必要が生じるトリガー
- 変更あたりのガバナンス費用と、プロジェクトの成長に伴うその変化
