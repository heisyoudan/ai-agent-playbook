# 08 — 真実のガバナンス

**日本語** · [English](README.md) · [简体中文](README.zh-CN.md)

**状態：Evolving。** 成熟度：**Observed Pattern（観察されたパターン）** — 成熟度ラベルの定義は[リサーチ・インキュベーター](../research/README.ja.md)を参照。本章の本文は現在[簡体字中国語](README.zh-CN.md)のみで公開しており、このページは同じ章の骨格である。

本リポジトリでいう Truth（真実）とは、証拠に支えられ、意思決定の根拠として使える事実を指す。

## この章が扱う問い

Agent が失敗するのは、出力を作れないからではない。古い事実、欠けた事実、あるいは存在しない事実を前提に動き、しかもそれに気づく責任者がワークフロー上にいないからだ。

では、プロジェクトは何を真実とみなすのか。それはどこに置かれ、誰が最新に保つのか。

## なぜこの章が必要か

第01〜07章は、Agent の周囲の仕事を信頼できるものにする。タスクを小さくし、コンテキストを閉じ、制約を明示し、検証し、引き継ぐ。これらの実践は「Agent が受け取る事実は信頼できる」という前提の上に成り立っている。

しかし、プロジェクトが1セッションより長く続くと、この前提は崩れる。同じ問いに三か所で異なる答えがある。先月記録された決定がコードに反映されていない。Agent が空欄をもっともらしい推測で埋め、次の Agent がそれを事実として継承する。

真実のガバナンスは、プロジェクトの真実を、生成・所有・失効させる対象として扱う。たまたま手に入る背景情報としては扱わない。

## この章に属すると想定される概念

- 現実、プロジェクトの真実、そしてその差
- 事実・決定・仮定・未解決の問いを、異なる型として区別すること
- 真実の情報源、所有権、変更権限
- 事実に付随する証拠と、証拠が失効したときに起きること
- 陳腐化、失効、ドリフトが可視化される仕組み
- 文書・コード・会話の間で真実が衝突する場合
- 真実を、独立した活動ではなく、すべてのタスクコンテキストの入力として扱うこと

## 現在の成熟度

実ワークフローで観察されているが、語彙はまだ安定していない。真実を統治可能にする仕組みの一部は検証中である。
