# 附录E — 概念权威地图（Concept Authority Map）

**简体中文**（其他附录已有英日版本；本附录目前只有中文版本）

这个索引用来回答四个问题：

- 一个概念是什么意思？
- 它最早在哪里出现？
- 哪一章拥有它的权威定义？
- 它和哪些相邻概念容易混淆？

> **本附录不重新定义方法论。** 每个概念的权威来源是章节正文；这里只做索引、归属和区分。
>
> **一个概念只能有一个权威章节。** 其他章节使用它时，属于引用或扩展，而不是重新定义。跨章节概念的唯一归属见「[权威归属](#权威归属)」。

它的另一个用途是**防止概念无限增殖**：当你想到一个新词时，可以先在这里查，它是不是已有概念的别名、应该属于哪一章、还是真的构成了一个新问题。

## 怎么使用

- 想知道某个概念归哪一章 → 看「[概念所有权一览](#概念所有权一览)」。
- 想知道两个词是不是一回事 → 看「[容易混淆的概念组](#容易混淆的概念组)」。
- 想快速查定义 → 看按 Part 组织的三张表。
- 想知道某个概念有多成熟 → 看「[成熟度说明](#成熟度说明)」。

「首次出现」指这个概念第一次被正式引入的章节。「权威章节」指它的定义所在。两者不同的地方会单独标注。

## 容易混淆的概念组

这是本附录最有价值的部分：单独定义不足以防止误用，更需要把相邻概念放在一起对照。

### State / Evidence / Truth

```text
State      = 当前执行到哪里
Evidence   = 发生了什么、有什么支持这个结论
Truth      = 当前被授权继续依赖什么
```

三者混在一起，工作流会逐渐失去可靠性。→ 14 / 11 / 08

### Gate / Verdict

```text
Gate     = 是否允许状态继续转换的机制
Verdict  = 验证角色对当前结果做出的判断
```

Gate 是状态控制，Verdict 是判断结果。不要互换。→ 14

### Retry / Reexecution / Recovery / Rollback

```text
Retry         = 在同一意图和条件下再次尝试
Reexecution   = 根据当前现实重新执行相关步骤
Recovery      = 中断或失败以后恢复到可以继续的状态
Rollback      = 把现实或系统状态恢复到先前状态
```

记住两句话：

```text
重新执行 ≠ 从断点继续
恢复 ≠ 回滚
```

→ 14（回滚与状态写入的区别另见 06）

### Capability / Authority

```text
Capability  = 能否可靠完成
Authority   = 是否有权决定或执行
```

> **能力不自动产生权限。**

→ 17 / 12 / 22

### 真相投影 / 个人真相投影 / 决策投影

```text
真相投影        = 当前任务可以相信什么
个人真相投影     = 当前问题需要知道这个 Human 的哪些相关现实
决策投影        = 执行层当前被授权实现什么
```

三者同族但对象不同，不要混用。→ 13 / 20 / 23

### 记忆 / 个人真相

```text
记忆       = 过去被保存的信息
个人真相    = 当前允许系统在判断中依赖什么
```

> **保存过，不代表现在仍然应该相信。**

→ 20

### Task Completion / Goal Completion

```text
Task Completion  = 局部工作已经完成
Goal Completion  = Human 做这个决定想实现的现实结果已经发生
```

代码完成不等于客户问题消失。→ 23

## 成熟度说明

索引中的概念不会因为被收录就自动视为同等成熟。

各章节正文的状态和成熟度仍然以对应章节为准。特别地：

- **`Human + AI Capability` 目前仍然是工作假设**，它解释力强，但证据有限。请把它当问题读，而不是当成已经成立的结论。
- **`上下文树` 目前是理解模型**，不是数据结构规范，也不是已经验证的机制。
- 01–07 的概念来自较早期的个人实践；它们的价值在于提出最前面的问题，而不是给出完整机制。
- 08–12 标记为 `持续演化（Evolving）`；13–24 标记为 `持续研究（Research）`，并带各自的成熟度标签。
