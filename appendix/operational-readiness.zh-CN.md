# 附录D — 生产就绪与治理检查表

[日本語](operational-readiness.ja.md) · [English](operational-readiness.md) · **简体中文**

只有良好的任务设计，并不足以支撑生产运行。权限、数据、责任、评估方法和停止条件也必须明确。本检查表用于把 Playbook 从个人实践扩展到团队与组织。

---

## 1. 先划分风险等级

| 风险 | 示例 | 默认治理强度 |
|---|---|---|
| **低** | 文案、说明、局部重构 | 自动执行；检查变更与自动验证结果 |
| **中** | 依赖变更、数据库迁移、用户可见行为 | 提高验证独立性；明确授权范围；准备回滚方案 |
| **高** | 认证、支付、个人信息、法规、生产发布 | 独立审查与完整证据；明确责任主体与 Human Gate |
| **禁止** | 未经批准删除生产数据、外传密钥、不可逆的外部动作 | 不向 Agent 授予该能力 |

风险等级取决于失败影响、影响范围和可逆性，而不是对模型能力的信心。

风险越高，五个维度同时收紧：

```text
验证独立性     更强
授权要求       更高
证据完整性     更完整
责任主体       更明确
恢复与停止     更严格
```

这五个维度分别由第 [12](../12-authority-human-gates/README.zh-CN.md) 章（决策权）、第 [14](../14-workflow-runtime-recovery/README.zh-CN.md) 章（运行时与恢复）、第 [16](../16-scalable-governance/README.zh-CN.md) 章（规模化治理）和第 [17](../17-capability-boundaries/README.zh-CN.md) 章（能力边界）讨论。

## 2. 最小化数据与权限

- 只提供任务必需的文件和数据。
- 不把密钥、个人信息或客户数据直接粘贴到提示词和日志中。
- 把读取、写入、联网和生产操作视为四类独立权限。
- 使用限定用途和有效期的短期凭证。
- 检查每个模型、服务和插件的数据保留、训练及传输条款。

授予完成当前任务所需的最小权限，而不是为了方便 Agent 而开放最大权限。

## 3. 明确人的审批点

以下操作应在执行前获得明确批准：

- 生产环境变更；
- 数据删除、覆盖或迁移；
- 付款、采购、发布、发送消息等外部作用；
- 认证、授权、加密或支付逻辑变更；
- 引入新的外部依赖、服务或插件；
- 法务、隐私与合规判断。

审批人需要检查变更、影响、验证证据和恢复方案，而不是只看 Agent 是否“有信心”。

这些操作需要 Human Gate，不是因为某个技术问题「AI 永远无法判断」，而是因为它们的失败影响、不可逆性和责任归属要求更高强度的验证与授权。相关原则见第 [12](../12-authority-human-gates/README.zh-CN.md) 章。

## 4. 衡量结果

| 维度 | 指标示例 |
|---|---|
| **速度** | 从开始到验收的时间、等待审查的时间 |
| **质量** | 返工率、漏出缺陷、任务重开率、越界变更数 |
| **验收** | 人工审查时间、自动检查覆盖率、证据缺失率 |
| **经济性** | 每个已验收任务的模型成本、重试次数、计算时间 |
| **运维性** | 人工介入率、例外率、回滚率、恢复时间 |

推广前先记录基线，再在有限的任务类型上比较。产出更快但返工或事故更多，并不算成功。

## 5. 分离工作状态与证据

Agent 使用的工作上下文应保持精简。发布、审计或事故调查需要的以下信息，应另行保留：

- 已批准的需求和决策；
- 变更文件与目标版本；
- 测试、环境、时间和结果；
- 质量门判定与审批人；
- 例外、驳回和回滚原因；
- 必要范围内的模型与工具标识。

“只读取最新状态”不等于“删除历史证据”。

## 6. 定义停止、降级与恢复条件

出现以下情况时，停止自动执行并把控制权交还给人：

- 同一失败反复出现，且没有形成新假设；
- 超过预设的时间、费用或重试次数；
- 修改扩散到批准范围之外；
- 规格、测试与运行证据相互矛盾；
- 出现隐私、密钥或安全风险；
- 无法确认回滚方式。

停止时应结构化交接背景、当前状态、证据、已尝试方案和未完成项。

## 7. 渐进推广

```text
选择一种低风险任务
  ↓
记录基线与成功条件
  ↓
试运行两到四周
  ↓
复盘质量、速度、成本与例外
  ↓
调整质量门与权限
  ↓
扩展到下一类任务
```

不要一开始就自动化整个生命周期。在看清例外类型和验收成本之前，保持范围有限。

## 上线前检查

```text
□ 风险等级与责任人已明确
□ Agent 权限遵循最小权限原则
□ 密钥和个人信息处理规则已定义
□ 需要事前批准的操作已列出
□ 验收标准与回滚步骤已具备
□ 速度、质量和成本基线已记录
□ 工作状态与长期证据使用不同的存储位置
□ 停止条件与升级负责人已定义
```
