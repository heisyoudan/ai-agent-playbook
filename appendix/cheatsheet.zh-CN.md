## 三条核心原则

```text
1. AI 是执行层。
2. 流程创造生产力。
3. 约束带来稳定性。
```

## Part I — 个人 AI 工程（01–07）

### 任务设计五原则

| # | 原则 | 自问 |
|---|---|---|
| 1 | 一个任务，一个目标 | 是否混合了多个结果？ |
| 2 | 定义完成 | 什么可观察证据代表完成？ |
| 3 | 定义边界 | 哪些内容不得修改？ |
| 4 | 保证可验证 | Agent 能否测试或检查结果？ |
| 5 | 闭合上下文 | 所需信息是否集中在一起？ |

### 最小任务契约

```text
summary:             预期结果
currentAction:       本次执行内容
acceptanceCriteria:  可观察的完成证据
boundaries:          禁止修改和非目标
```

四项完整之前，不要交接任务。

### 提示词质量四个维度

| 维度 | 检查 |
|---|---|
| 信息密度 | 每句话是否都会影响执行？ |
| 任务边界 | 范围和非目标是否明确？ |
| 上下文质量 | 是否删除了无关历史？ |
| 约束清晰度 | 隐含期待是否已经说清？ |

### 上下文隔离

职责变化、当前状态难以重述、反复回到旧话题或输出质量下降时，开启新会话。交接应包含目标、决策、规格、约束、证据和验收标准。

### 多 Agent 管理六要素

```text
1. 角色       → 谁负责什么
2. 约束       → 每个角色不得做什么
3. 汇报       → 变更、原因、证据、剩余工作
4. 验收       → 客观完成条件
5. 失败处理   → 停止、记录、升级、恢复
6. 交接       → 阶段间明确传递状态
```

### 工作流设计

| 原则 | 含义 |
|---|---|
| 模板驱动 | 遵循规定路径，异常时进入规定案例 |
| 压缩正常路径 | 替换和打磨规则，而不是无限增加 |
| 质量门 | 证据不完整时阻止状态转换 |
| 原子状态转换 | 同时记录原因、改变状态并交接 |
| 单一事实来源 | 在一个结构化系统中维护权威状态 |

## Part II — 可靠 Agent 软件工程（08–17）

| 概念 | 一句话原则 | 章节 |
|---|---|---|
| 真相治理 | Agent 必须知道当前哪些事实被授权为可信真相。 | 08 |
| 有效推理范围 | 能放进上下文，不等于能够可靠推理。 | 09 |
| 边界与契约 | 切分不会消灭复杂度，只会把它转移到边界协调。 | 10 |
| 证据闭环 | 完成结论必须由仍然有效、并且覆盖声明的证据支撑。 | 11 |
| 决策权 | 决策权不能超过验证能力。 | 12 |
| 真相投影 | 局部世界只接收当前决策需要的全局真相子集。 | 13 |
| Runtime 与恢复 | 会话恢复不是工作流恢复，检查点不是恢复游标。 | 14 |
| 边界协调成本 | 最优边界是「AI 看得清」同时「系统付得起」。 | 15 |
| 规模化治理 | 治理本身也有成本，规则应该在哪一层闭合。 | 16 |
| 能力边界 | 能够实现，不代表能够可靠交付。 | 17 |

## Part III — Human × AI 长期协作（18–24）

| 概念 | 一句话原则 | 章节 |
|---|---|---|
| AI 角色演化 | 角色范围扩大，不等于获得最终决定权。 | 18 |
| 长期个人上下文 | 聊天历史不等于长期个人上下文。 | 19 |
| 个人真相 | 保存过，不代表现在仍然应该相信。 | 20 |
| 决策支持 | 机会本身的质量，不等于机会对这个人的适配度。 | 21 |
| 决策边界 | 理解不等于授权。 | 22 |
| 执行授权 | 决定不是任务。 | 23 |
| 现实反馈 | 现实结果既是终点，也是下一轮输入。 | 24 |
| 上下文树 | 长期价值来自结构，而不是记忆数量。 | 19 / 24 |

## 验证清单

```text
□ Agent 完成了适用的自我检查
□ 已审查变更文件和差异
□ 没有范围之外的修改
□ 可机器验证的检查已经自动化
□ 安全、架构和业务逻辑经过人工审查
□ 结论有官方资料或运行证据支持
□ 受阻 Agent 已停止并输出结构化报告
```

## 失败模式

六个高频基础失败模式，完整定义见[附录A](anti-patterns.zh-CN.md)。其余失败模式按章节分布，索引同样在附录A。

| # | 模式 | 对策 |
|---|---|---|
| 1 | 先改状态、后写日志 | 让转换成为原子操作 |
| 2 | 任务不完整就交接 | 强制四个字段 |
| 3 | 一个会话做所有事 | 每个会话一个职责 |
| 4 | 手工重复规则 | 对共享指令进行版本管理 |
| 5 | 把工作输出当档案 | 分离状态与证据 |
| 6 | 善意越界 | 明确禁止事项和非目标 |
