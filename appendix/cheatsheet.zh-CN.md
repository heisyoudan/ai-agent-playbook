# 附录C — 速查表

[日本語](cheatsheet.ja.md) · [English](cheatsheet.md) · **简体中文**

## 三条核心原则

```text
1. AI 是执行层。
2. 流程创造生产力。
3. 约束带来稳定性。
```

## 任务设计五原则

| # | 原则 | 自问 |
|---|---|---|
| 1 | 一个任务，一个目标 | 是否混合了多个结果？ |
| 2 | 定义完成 | 什么可观察证据代表完成？ |
| 3 | 定义边界 | 哪些内容不得修改？ |
| 4 | 保证可验证 | Agent 能否测试或检查结果？ |
| 5 | 闭合上下文 | 所需信息是否集中在一起？ |

## 最小任务契约

```text
summary:             预期结果
currentAction:       本次执行内容
acceptanceCriteria:  可观察的完成证据
boundaries:          禁止修改和非目标
```

四项完整之前，不要交接任务。

## 提示词质量四个维度

| 维度 | 检查 |
|---|---|
| 信息密度 | 每句话是否都会影响执行？ |
| 任务边界 | 范围和非目标是否明确？ |
| 上下文质量 | 是否删除了无关历史？ |
| 约束清晰度 | 隐含期待是否已经说清？ |

## 上下文隔离

职责变化、当前状态难以重述、反复回到旧话题或输出质量下降时，开启新会话。交接应包含目标、决策、规格、约束、证据和验收标准。

## 多 Agent 管理六要素

```text
1. 角色       → 谁负责什么
2. 约束       → 每个角色不得做什么
3. 汇报       → 变更、原因、证据、剩余工作
4. 验收       → 客观完成条件
5. 失败处理   → 停止、记录、升级、恢复
6. 交接       → 阶段间明确传递状态
```

## 工作流设计

| 原则 | 含义 |
|---|---|
| 模板驱动 | 遵循规定路径，异常时进入规定案例 |
| 压缩正常路径 | 替换和打磨规则，而不是无限增加 |
| 质量门 | 证据不完整时阻止状态转换 |
| 原子回滚 | 同时记录原因、改变状态并交接 |
| 单一事实来源 | 在一个结构化系统中维护权威状态 |

## 验证清单

```text
□ Agent 完成了适用的自我检查
□ 已审查变更文件和差异
□ 没有范围之外的修改
□ 可机器验证的检查已经自动化
□ 安全、架构和业务逻辑经过人工审查
□ 结论有官方资料或运行证据支持
□ 受阻 Agent 已停止并输出结构化报告
```

## 失败模式

| # | 模式 | 对策 |
|---|---|---|
| 1 | 先改状态、后写日志 | 让转换成为原子操作 |
| 2 | 任务不完整就交接 | 强制四个字段 |
| 3 | 一个会话做所有事 | 每个会话一个职责 |
| 4 | 手工重复规则 | 对共享指令进行版本管理 |
| 5 | 把工作输出当档案 | 分离状态与证据 |
| 6 | 善意越界 | 明确禁止事项和非目标 |

## 最后的问题

```text
没有我，这个系统还能复现同样的质量吗？

能 → 它已经是流程。
不能 → 它仍然依赖个人能力。
```
