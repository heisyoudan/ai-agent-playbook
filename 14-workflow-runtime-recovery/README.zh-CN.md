# 14 — 工作流运行时与恢复

[日本語](README.ja.md) · [English](README.md) · **简体中文**

**状态：草稿（章节框架）。** 成熟度：**Observed Pattern（已观察到的模式）** —— 问题被持续观察到，但恢复机制仍在试验中。持续积累的证据记录在[研究孵化器](../research/README.zh-CN.md)中。

## 本章要回答的问题

工作流如何知道自己现在处在哪一步？被打断之后如何恢复？

## 为什么需要这一章

多步骤工作流会在中途失败：会话结束、工具超时、Agent 产出不可用的结果、门禁退回当前状态。

如果运行时状态只存在于对话里，所谓恢复就等于重新推导上下文——这通常是最昂贵、也最不可靠的选项。更糟的是它不可见：因为工作最终继续了，所以没有人把它记为一次失败。

和验证一样，恢复应当是经过设计的能力。也就是说，工作流必须能够回答自己：现在在哪、最后一个有效检查点是什么、哪些操作绝不能重复。

## 预计纳入的概念

- 运行时状态：工作流应当能回答哪些关于自身的问题
- 检查点，以及检查点有效的条件
- 恢复、重启与回滚的区别
- 幂等重执行与不可逆步骤的保护
- 部分失败及其可见状态
- 重试上限、升级与安全停止条件
- 恢复证据：证明重跑了什么、跳过了什么

## 当前成熟度

问题在真实工作流中被持续观察到；具体恢复机制仍在比较中，尚无确立做法。
