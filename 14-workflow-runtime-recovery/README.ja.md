# 14 — ワークフロー実行時状態と復旧

**日本語** · [English](README.md) · [简体中文](README.zh-CN.md)

**状態：ドラフト（章の骨格）。** 成熟度：**Observed Pattern（観察されたパターン）** — 問題は一貫して観察されているが、復旧の仕組みは検証中である。継続的な証拠は[リサーチ・インキュベーター](../research/README.ja.md)で追跡する。

## この章が扱う問い

ワークフローは自分が今どこにいるかをどう把握し、中断後にどう再開するのか。

## なぜこの章が必要か

複数ステップのワークフローは途中で失敗する。セッションが終わる、ツールがタイムアウトする、Agent が使えない成果物を出す、ゲートが現在の状態を差し戻す。

実行時状態が会話の中にしか存在しない場合、復旧とはコンテキストの再導出を意味する。多くの場合、それが最も高価で最も信頼できない選択肢である。さらに悪いことに、それは可視化されない。最終的に作業が続いてしまうため、誰も失敗として記録しない。

検証と同じく、復旧も設計された能力であるべきだ。つまりワークフローは、自分の現在位置、最後の有効なチェックポイント、そして繰り返してはならない操作を答えられる必要がある。

## この章に属すると想定される概念

- 実行時状態：ワークフローが自分自身について答えられるべき情報
- チェックポイントと、それが有効である条件
- 再開・再実行・ロールバックの区別
- 冪等な再実行と、不可逆ステップの保護
- 部分的な失敗とその可視化された状態
- 再試行の上限、エスカレーション、安全な停止条件
- 復旧の証拠：何を再実行し、何を省略したかを示すこと

## 現在の成熟度

問題は実ワークフローで一貫して観察されている。具体的な復旧の仕組みは比較検討中で、確立した方法はまだない。
