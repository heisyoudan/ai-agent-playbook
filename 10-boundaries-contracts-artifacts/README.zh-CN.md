# 10 — 边界、契约与产物

[日本語](README.ja.md) · [English](README.md) · **简体中文**

**状态：草稿（章节框架）。** 成熟度：**Derived Principle（推导出的原则）** —— 由第 02、06 章的实践推导而来，并在真实工作流中反复确认，但还不是完成形态的方法论。持续积累的证据记录在[研究孵化器](../research/README.zh-CN.md)中。

## 本章要回答的问题

如何把任务的边界说清楚，并让任务的成果能被下一位接手者直接使用？

## 为什么需要这一章

第 02 章定义了最小任务契约。它足够开工，但不足以让系统长期可靠，还缺三样东西：

- **边界**：不只是被提到，而是不能被越过
- **契约**：写明双方的义务，包括接收方必须提供什么
- **产物**：在不携带整段对话的前提下把状态传递下去

没有产物，下一个会话就得重新推导上一个会话已知的东西；没有契约，“完成”就由最后判断的人自行解释。

## 预计纳入的概念

- 边界类型：范围、变更、数据、权限、时间、预算
- 作为可验证义务的契约（对双方都成立）
- 产物设计：持久性、最小内容、归属、检索方式
- 工作状态与需留存证据的分离
- 交接产物及其必须包含的最小内容
- 人与 Agent 之间的契约，以及 Agent 之间的契约

## 当前成熟度

来自实践而非理论。边界分类在实务中已相对稳定，产物的约定仍在收敛过程中。
