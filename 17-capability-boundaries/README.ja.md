# 17 — 能力の境界

**日本語** · [English](README.md) · [简体中文](README.zh-CN.md)

**状態：ドラフト（章の骨格）。** 成熟度：**Working Hypothesis（作業仮説）** — 問題は観察されているが、能力を確立する方法はまだ開発途上である。追跡は[リサーチ・インキュベーター](../research/README.ja.md)で行う。

## この章が扱う問い

Agent は何を任せてよいのか。その信頼を支える証拠は何か。

## なぜこの章が必要か

能力は、たいてい「目の前の仕事の証拠にならないもの」から推測される。

- 一度うまくいった結果を、一般的な性質として扱う
- 他者のタスクで測られた公開ベンチマーク
- 出力に表れる自信

いずれも、このリポジトリで、このタスク種別で、この制約の下で、この Agent が何をできるかを示してはいない。能力の境界は、タスク種別ごとに観察結果から確立し、モデル・ツール・コンテキストが変わったときに改訂する方が有用である。

もうひとつ、丁寧に切り分けたい混同がある。**能力は権限ではない。** 第12章は Agent が何を決定してよいかを扱う。この章は何を任せられるかを扱う。しばしば一つの問いに混ざる、別の問いである。

## この章に属すると想定される概念

- 主張された能力と、示された能力
- 一般的な印象ではなく、タスク種別ごとの証拠
- 較正：自信と実際の結果の対応
- 長い作業、繰り返しの編集、不慣れなコードでの劣化
- モデル・ツール・コンテキストの変化に伴う能力のドリフト
- 能力と権限の区別

## 現在の成熟度

作業仮説である。区別自体は明確だが、能力の境界を確立する再現可能な方法はまだ確立していない。
