# 17 — 能力边界

[日本語](README.ja.md) · [English](README.md) · **简体中文**

**状态：草稿（章节框架）。** 成熟度：**Working Hypothesis（工作假设）** —— 问题已被观察到，但确立能力的方法仍在开发中。跟踪记录在[研究孵化器](../research/README.zh-CN.md)中。

## 本章要回答的问题

哪些工作可以交给 Agent？支撑这种信任的证据是什么？

## 为什么需要这一章

能力往往是从“并不构成眼前工作证据”的东西推断出来的：

- 把一次成功当作一般属性
- 在别人任务上测出的公开基准
- 输出本身表现出的自信

这些都没有说明：在本仓库、这类任务、这些约束下，这个 Agent 到底能做到什么。更有用的做法是按任务类型，从观察结果中确立能力边界，并在模型、工具或上下文变化时修订它。

还有一个需要仔细区分开的混淆：**能力不等于权限。** 第 12 章讨论 Agent 被允许决定什么，本章讨论它可以被依赖做到什么。这是两个经常被合并的问题。

## 预计纳入的概念

- 宣称的能力与已证明的能力
- 按任务类型的证据，而不是总体印象
- 校准：自信程度与实际结果的对应关系
- 长任务、反复修改或不熟悉代码时的能力衰减
- 模型、工具、上下文变化导致的能力漂移
- 能力与权限的区分

## 当前成熟度

工作假设。区分本身是清晰的，但还没有可重复地确立能力边界的方法。
